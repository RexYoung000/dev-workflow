# dev-workflow 产品需求文档

| 项 | 值 |
|---|---|
| 版本 | v1.1，Trae 项目级分发版 |
| 日期 | 2026-10-20 |
| 状态 | 已实现且代理验证通过；真实 Trae 点名烟测通过，用户完整体验待验收 |

## 1. 定位与用户

dev-workflow 是仅面向 **Trae 桌面端项目级安装**的开发流程包，包含 Skill、操作手册、模板和 Python CLI。主力验证对象为 Trae CN；国际版、旧版本与其他 IDE 不作兼容承诺。不开发 Web 面板、IDE 插件市场产品或多人协作平台。

使用者包括 Rex 与其他独立开发者。每个人将本包安装到自己的项目，使用自己的 GitHub 账号与仓库。源码仓库是分发来源，不是新项目模板；工作流自身的 PRD、任务、验收记录和状态不得带进消费项目。

## 2. 产品契约与事实源

- 触发：在已安装项目的新 Trae 会话中点名“用 dev-workflow 开始新项目 / 继续当前项目”，也允许相关任务自动匹配 Skill。
- 核心工作：六阶段推进需求、方案、Demo、Task/Issue、实施和测试验收。
- 本地业务文档及 `tasks/*.md` 是事实源；GitHub Issue 仅为单向创建/关闭镜像，不双向回写。
- Task 状态唯一事实源是 front-matter 的 `status`；`.workflow/state.json` 只保存项目阶段、仓库缓存及配置。
- 代理测试通过与用户体验验收分别记录；文档、Skill 被识别或脚本通过都不等同于用户验收完成。

## 3. 六阶段流程

| 阶段 | 工作与产出 | 完成门槛 |
|---|---|---|
| 1 需求 | 逐题澄清关键决策，维护业务 `docs/prd.md` | 用户确认需求 |
| 2 方案 | 技术选型、规范与风险验证点，维护 `docs/tech-spec.md` | 用户确认方案，或已明确授权按推荐实施 |
| 3 Demo | 最小使用闭环和技术风险验证 | Demo 跑通，关键风险有结论 |
| 4 Task/Issue | 按模块拆 Task，单向同步到自己的仓库 | Task 有效、依赖有效、Issue 编号齐备 |
| 5 执行 | 依据 Task 实施与验证，普通 commit/push | Task done、检查点全部完成且已推送 |
| 6 验收 | Agent 复查与用户实际使用验收 | 用户明确通过；缺陷回 5，新需求回 1 |

CLI 检查可机器判断的条件。用户确认、Demo 结果、实际推送和产品体验由 Agent 与用户核实，不能用一个阶段编号替代这些证据。

## 4. 安装与升级（P0）

1. 使用者 clone 分发仓库，通过 `python3 scripts/workflow.py install --target <项目根目录> --init` 完成首次安装；`--init` 可省略，稍后由 Skill 初始化。
2. 安装到 `<项目>/.trae/skills/dev-workflow/`，包内包含 CLI、模板、参考文件和许可，删除源码 checkout 后仍可运行。
3. 安装器只写本项目，不修改用户全局 Trae 配置，不依赖 Rex 的电脑路径或登录状态。
4. 生成一个轻量 `.trae/rules/dev-workflow.md` 入口；已有 AGENTS、规则和业务文档保持原样。没有 AGENTS 时生成适用于消费项目的简短指引，不将项目描述成 dev-workflow 本体。
5. 初始化从阶段 1、空 Task 开始，从目标项目自己的 origin 识别仓库；没有远端时允许本地规划，进入 Issue 同步前再配置。
6. 升级只替换安装包，覆盖前在项目 `.trae/.dev-workflow-backups/` 保留可恢复副本；不覆盖业务文档、任务、阶段或自定义模板。重复安装同一版本内容应无副作用。
7. 发现已有 workflow 状态与 origin 不一致时拒绝同步/初始化覆盖，说明需核对仓库与 Issue 映射，不静默迁移。

## 5. 任务、同步与调度（P0）

- Task 字段：id、title、module、status 必填；deps、issue、assignee 可选；正文含描述和验收 checkbox。
- 状态为 todo / in-progress / review / done / blocked；done 需至少一条实际验收 checkpoint 且全部勾选。
- 非法字段、重复 ID、缺失依赖、依赖环和未完成的 done 检查点必须可见，并阻止阶段推进。同步跳过异常 Task，继续处理有效 Task，最后非零退出提示有异常。
- GitHub origin 为同步目标依据。缓存 repo 不一致、未登录、Issues 未开启或权限不足时，在任何写入前报错。
- 无 Issue 的 Task 按 ID 查重后创建/回填；done 的关闭；重复运行不制造重复 Issue。现有 Issue 正文不持续更新，远端编辑不回写；归档不承诺实时双向看板。
- 并行预览只提供依赖全部 done 的候选，每模块最多一个，受 max_parallel 限制；不把依赖未完成的任务标为可执行。不同模块不等于一定无文件冲突，Agent 仍检查共享文件。
- 并发是可选增强。仅在当前 Trae 版本和内置 Agent 已具备相应子智能体能力时使用，否则串行完成，不要求额外安装 MCP。

## 6. 公开分发与限制

- Python ≥3.9 标准库、Git 为本地使用前置；GitHub CLI、自有账号登录、可写且启用 Issues 的仓库为同步和阶段 4 → 5 的前置。
- 提供 README：安装、Trae 入口、配置仓库、更新/回退、常见失败与验证范围。Windows 可使用 `py -3` 替代 `python3`，未实测平台明确标注。
- 用户选定 MIT 许可（2026-10-20），安装包携带许可；项目本身的业务代码许可由项目所有者决定。
- 本期不支持多人共用工作目录的并发写入、不自动执行 GitHub 发布、生产部署、PR 合并或配置全局工具。
